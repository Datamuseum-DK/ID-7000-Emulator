Two emulators have been in use for this project. One is based on 
a similar project for the Q1 Microlite micro computer.

the documentation effort we refer to:

https://q1-lite-emulator.readthedocs.io/en/latest/

Claude i8080 emulator
======================

But for ID-7000A the novel thing is that I have been prompting 
Claude to help with the reverse engineering.

This turned out to provide results much faster than I am able to 
do.

This has resulted in the development of a new i8080 emulator. While 
being very similar in the ideas I used it is currently smaller in 
size, fully written in python and has some nicer abstractions.

It was used by Claude to test its guesses and could be used as the 
basis for further developments of ID-7000 A. So far I didn't repeat the 
exercise for ID-7000 SPS/FUNK.
 
Below is the documentation generated by Claude

The Python emulator
===================

Files
-----

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - File
     - Purpose
   * - ``cpu8080.py``
     - 8080 core (documented opcodes). ``CPU8080(bus)`` with
       ``step()``, ``interrupt(n)`` (RST n), and register-pair properties.
   * - ``machine.py``
     - ``Bus`` (ROM at ``0000h``, RAM above, ROM writes ignored), ``USART``
       (minimal 8251) and ``Machine`` (12 channels, timer tick, console
       helpers).
   * - ``sync.py``
     - ``Sync8251`` (sync-mode 8251 at ``A0h``/``A1h``), ``frame()`` helper,
       ``attach()`` to wire the sync line into a machine, and ``CyberHost``
       (stub host).
   * - ``demo.py``
     - Console demonstration (local commands).
   * - ``demo_cyber.py``
     - Cyber-link demonstration.
   * - ``id7000_rom.asm``
     - The annotated 8080 disassembly.

Machine model
-------------

* ROM: ``board5_eproms_0_to_6.bin`` at ``0000h``; RAM ``4000h``-``BFFFh``
  (the whole 64 KB array is writable above the ROM for simplicity).
* ``Machine.TICK = 2500`` CPU steps per RST 3 tick. **This is a guess.**
* Each 8251 reports status ``05h`` (TxRDY and TxEMPTY) and adds ``02h``
  (RxRDY) when a byte is queued.
* The sync 8251 implements the mode / sync-character / command sequence and
  reports TxRDY only while transmit is enabled; ``attach()`` raises RST 4
  periodically while it is.

Basic usage
-----------

.. code-block:: python

   from machine import Machine

   m = Machine()
   m.boot()                    # run self-test, idle loop, banner

   m.type(":STATUS\r")         # feed characters into channel 0 (RST 6 each)
   m.run(900000)               # let the slow transmitter finish
   print(m.take_tx())          # bytes the terminal sent on channel 0

Example output (``demo.py``):

.. code-block:: text

   ':STATUS' -> |[ASCII NORMAL MODE (95 CH-SET)]|[NO CR/LF AT LINES WITH 80 CHARS]|...
   ':HP,ON'  -> |[HP-CASSETTE MODE ON]|
   ':FOO'    -> |[ILLEGAL COMMAND]|
   'HELLO'   -> |[CYBER LINK DOWN]|

Using the Cyber host stub
-------------------------

.. code-block:: python

   from machine import Machine
   from sync import Sync8251, CyberHost, attach

   m = Machine()
   s = Sync8251()
   attach(m, s)            # wire A0h/A1h and RST 4 into the machine
   m.boot()
   host = CyberHost(m, s)

   host.poll()                          # idle reply, link comes up
   m.type("HELLO\r"); m.run(500000)     # queued for the host
   host.poll()                          # reply carries "HELLO ESC B"
   host.say(0, b"HI FROM CYBER\r\n")    # appears on channel 0's console

Caveats on the emulator
-----------------------

* ``cpu8080.py`` implements the documented opcodes. No instruction-exerciser
  test (8080EXER, TST8080) has been run; the checksum, RAM test and command
  handling all pass, which is only partial evidence of correctness.
* The 8251, 8255 and timer behaviour is inferred from initialisation
  sequences and code, not from datasheets.
* The firmware transmits slowly, so output from one command can still be
  coming out during the next; run extra steps (``m.run(400000)``) after a
  line before reading the output.
